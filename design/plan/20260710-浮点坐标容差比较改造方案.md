# 浮点坐标容差比较改造方案

日期：2026-07-10

## 背景

项目中大量使用 `==`/`!=` 对 `qreal`（即 `double`）坐标直接比较，而 Qt 坐标经过多次矩阵变换（缩放/平移/旋转）后会产生浮点误差，精确相等判断不可靠。

已有 `qFuzzyCompare`/`qFuzzyIsNull` 用于容差比较，但只覆盖少数位置。

## 问题清单

共 11 处 14 个表达式，分类如下：

### A 类：`ConductorSegment` 方向判断（2处）

| 文件 | 行 | 表达式 | 函数 |
|---|---|---|---|
| `sources/conductorsegment.cpp` | 447 | `point1.x() == point2.x()` | `isVertical()` |
| `sources/conductorsegment.cpp` | 455 | `point1.y() == point2.y()` | `isHorizontal()` |

**分析**：此判断影响导线路由、文本位置计算。栅格对齐场景下 x/y 应完全一致，但不使用栅格时可能出现微小偏差。

## 改造方案

### 方案一：`qFuzzyCompare` 替换（推荐，低风险）

对所有位置直接替换为 Qt 内置容差比较。

| 类 | 原表达式 | 替换为 |
|---|---|---|
| A/B/D/E | `a == b` (qreal) | `qFuzzyCompare(a, b)` |
| A/B/D/E | `a != b` (qreal) | `!qFuzzyCompare(a, b)` |
| C/F/G/H/I | `point == other` (QPointF) | `qFuzzyCompare(point.x(), other.x()) && qFuzzyCompare(point.y(), other.y())` |
| C/F/G/H/I | `rect == other` (QRectF) | `qFuzzyCompare(rect.x(), other.x()) && qFuzzyCompare(rect.y(), other.y()) && qFuzzyCompare(rect.width(), other.width()) && qFuzzyCompare(rect.height(), other.height())` |

**注意**：`qFuzzyCompare` 对接近零的值行为特殊（`qFuzzyIsNull`）。零值和负值在 `qFuzzyCompare` 下视为不相等。如果原逻辑预期处理零值，需额外处理。

### 方案二：自定义容差常量 `QET::tolerance`

定义 `namespace QET` 中的全局容差常量，所有比较统一使用。

```cpp
namespace QET {
    static constexpr qreal TOLERANCE = 1e-9;
    inline bool fuzzyCompare(qreal a, qreal b) {
        return qAbs(a - b) <= TOLERANCE;
    }
    inline bool fuzzyCompare(const QPointF &a, const QPointF &b) {
        return fuzzyCompare(a.x(), b.x()) && fuzzyCompare(a.y(), b.y());
    }
    inline bool fuzzyCompare(const QRectF &a, const QRectF &b) {
        return fuzzyCompare(a.topLeft(), b.topLeft()) &&
               fuzzyCompare(a.bottomRight(), b.bottomRight());
    }
}
```

**优点**：统一控制容差、避免 `qFuzzyCompare` 的零值特例问题。

### 方案三：只修复有副作用的（保守）

只修复可能导致行为偏差的：

- A/B 类（方向判断）：影响 conductor 路由，必须修复
- E/F/G/H/I 类（去重/守卫）：影响 undo、event 处理
- C 类（排序稳定性）：影响终端排序
- D 类（signal 发射）：允许少量冗余 signal，可暂缓

## 风险

1. `qFuzzyCompare` 对 `0.0` 输入会回退到 `qFuzzyIsNull`，即 `qAbs(a) <= 1e-12`。如果两个值都是很小的非零数（如 `1e-15`），`qFuzzyCompare` 返回 false，而直接 `==` 也返回 false，无行为变化。
2. 方案一改动最小但依赖 Qt 行为。方案二需新增文件/函数，但有长期维护优势。

## 推荐方案

**方案一**（`qFuzzyCompare` 替换）作为近期修复，最快最安全。各位置单独评审即可。完整修改约 14 处表达式，分散在 8 个文件中。
